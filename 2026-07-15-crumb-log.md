## What happened

**Installed and first real-world run.** Banner Scout 0.1.0 loaded unpacked
(ID `gcffccjdcafmlbefiiaflhokekjpkcnh`). xian confirmed CNN and Stack Overflow
banners intercepted. BBC didn't show one — expected, since a prior consent
cookie suppresses it. Reminder issued: the old "Smart Cookie Banner Handler"
auto-clicker was still installed/enabled and should be **removed** so it
doesn't click banners before Scout sees them (contaminates the experiment).

**Found and fixed the w3schools hang (first field bug).** Symptom: page stuck
behind a dimmed backdrop + spinner, unusable. Root cause: w3schools uses Fast
CMP (`static.fastcmp.com`), which renders a consent dialog plus a *separate*
text-free dimming backdrop as a sibling, and locks body scroll. Scout hid the
dialog correctly but left the orphan backdrop, so the page stayed dimmed and
locked.

Fix (`sweepBackdrops`, commit `35df975`): after hiding a banner, sweep the top
two levels under `<body>` for fixed, near-full-viewport (>70%), high-z-index
(>=50), effectively text-free layers with no labeled controls, and hide them;
also release the scroll lock (now handles `position:fixed` body locks too).
Reproduced the exact symptom in the harness with a Fast-CMP-style modal, then
confirmed the fix: dialog + backdrop both cleared, scroll restored, login
modal and article still untouched.

## Notes / watch-list

- **Log dedupe caveat:** the same site re-shows its banner every visit (we
  never set a consent cookie). Fine for measurement, but "remember we hid
  this" may become a UX item if it gets annoying.
- **Iframe blind spot, sharpened:** if a CMP renders its dialog inside a
  cross-origin iframe but its backdrop in the top frame, Scout hides nothing
  and never sweeps — user would see the iframe dialog AND be stuck. Still the
  documented iframe gap; the backdrop sweep only runs after a top-frame hide.
- Roadmap unchanged: GPC signaling next candidate, then iframe CMPs.

**Built GPC signaling — v0.2.0 (commit `ef641d9`).** Both signal surfaces:
- `Sec-GPC: 1` request header via a `declarativeNetRequest` static ruleset
  (`rules.json`) — the half servers act on, with legal force under CCPA/CPRA.
- `navigator.globalPrivacyControl = true` via a `document_start` MAIN-world
  content script (`gpc.js`) — verified in the browser pane (undefined → true).
- Manifest now requests `declarativeNetRequest` + `<all_urls>` host permission.
  **Trade-off flagged:** this reintroduces the broad host permission v0.1.0
  deliberately shed. GPC without the header is only half the signal, so it's a
  deliberate choice, documented in the README. GPC is global + always-on for
  now; runtime toggle + per-site control need a background worker (roadmapped).
